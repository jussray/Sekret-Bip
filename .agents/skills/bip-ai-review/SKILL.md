# bip-ai-review

## 5W1H operating contract

Before planning, editing, or claiming completion, establish and state:

- **Who** — the requester, decision owner, affected users, data subjects, and execution authority.
- **What** — the requested outcome, concrete deliverable, non-goals, and existing work that must be preserved.
- **Where** — the exact repository, branch, environment, runtime, route, service, table, or provider boundary involved.
- **When** — the current lifecycle or release state, required ordering, timing constraint, and rollback window.
- **Why** — the user problem and verified evidence that justify the work.
- **How** — the smallest safe implementation, required permissions, verification evidence, rollout, and rollback.

Inspect repository and runtime truth for unknowns. Ask the user only when a missing answer would materially change the safe solution or authority. Re-run 5W1H after red-team/OODA findings change the plan. Finish by mapping the result, evidence, remaining blocker, and next owner back to these six questions.


## Trigger
Any PR or task touching: `worker/sekret-reply.ts`, `worker/companion-curriculum.ts`,
`constants/bip_voice.ts`, `constants/guardrails.ts`, `constants/parentSekret.ts`,
or any file containing system prompts, persona config, or AI memory logic.

## The AI Stack (verified file locations)
```
worker/sekret-reply.ts          — character AI brain, prompt construction, reply generation
worker/companion-curriculum.ts  — companion learning progression logic
worker/bridge-summary.ts        — AI-generated summaries for parents
constants/bip_voice.ts          — character voice definitions (source of truth for persona)
constants/guardrails.ts         — safety boundaries and banned response patterns
constants/parentSekret.ts       — parent-facing AI character config
```

## Review Protocol

### 1. Prompt Integrity
- [ ] System prompt still begins with the character's locked voice profile from `bip_voice.ts`
- [ ] No user-supplied text is interpolated into the system prompt (injection risk)
- [ ] Character tone, vocabulary, and sentence style match the bip_voice.ts profile
- [ ] Run bip-voice-guard on all new user-facing strings generated by the AI

### 2. Guardrails Integrity
- [ ] `constants/guardrails.ts` boundaries are still applied after any prompt changes
- [ ] No guardrail has been commented out, weakened, or reordered lower in the prompt stack
- [ ] Clinical language ban is still enforced (cross-reference bip-voice-guard)
- [ ] Crisis/safety response logic is unchanged or strengthened — never weakened

### 3. Memory Usage
- [ ] Memory context injected into prompts contains ONLY the current user's own data
- [ ] No cross-user memory bleed — memory queries must be scoped to `auth.uid()`
- [ ] Memory payload does not include raw PII (real name, location, age if avoidable)
- [ ] Memory size is bounded — no unbounded conversation history injected

### 4. Companion Consistency
- [ ] Character persona is immutable at runtime — user cannot modify core voice via chat
- [ ] Parent-facing AI (parentSekret.ts) does not share prompts or memory with teen AI
- [ ] Each character's voice remains distinct after the change — run a spot-check with
  a sample prompt and verify the tone matches the bip_voice.ts profile

### 5. Model / API Changes
- [ ] Any model version change is explicitly noted in the PR description
- [ ] New API keys or endpoints are added to `.dev.vars.example`
- [ ] Fallback behavior on model timeout/error is defined and safe (no raw error to user)

### 6. Teen Safety Specific
- [ ] AI cannot be prompted into providing self-harm methods, substances, or unsafe advice
- [ ] Escalation path (to trusted adult or resource) is still wired for crisis keywords
- [ ] AI never claims to be a real person or licensed professional

## Output
Return: APPROVED | CHANGES REQUIRED | ESCALATE
- ESCALATE: any change that weakens teen safety guardrails — requires explicit author sign-off
- CHANGES REQUIRED: exact file + line + rule
- Note which character(s) are affected by the change
