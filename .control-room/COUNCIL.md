# Founder AI Council Contract

Status: active control-room documentation for `jussray/Sekret-Bip`.

The Council is a reasoning and review layer. It cannot override current repository/provider/runtime evidence, privacy/consent boundaries, or founder authority.

## Members

- **Founder**: final human authority for separately gated actions.
- **Chief AI**: orchestration, decomposition, and synthesis; never self-authorizes execution.
- **Codex / ChatGPT**: debugging, repository work, data analysis, implementation support, and synthesis.
- **Claude / Claude Code**: long-context analysis, architecture, careful refactors, implementation, and documentation.
- **Muse**: first-class governed challenger for GitHub/Supabase/Cloudflare drift, independent review, and bounded implementation. Prefer Standard / non-contributor mode for proprietary context unless explicitly authorized otherwise.
- **Perplexity**: current public research/source discovery; public web evidence does not substitute for Se’kret Bip private/runtime truth.
- **Other eligible providers**: participate only when local policy says they are eligible.

## Privacy and safety rule

The Council does not need raw teen/private content to reason about most product, code, infrastructure, or launch questions. Do not distribute journal text, voice/media, private messages, teen/parent identities, email addresses, private database rows, service-role keys, model keys, session tokens, or protected user content across Council members.

Use minimized operational receipts, synthetic fixtures, schemas, contracts, and redacted evidence instead. A Council seat never expands consent.

## Council rules

1. Evidence outranks model opinion.
2. Consensus does not authorize mutation.
3. Preserve meaningful dissent.
4. Parallel reasoning is allowed; mutation is serialized.
5. Bind every round to repository/project, current branch/head, provider surfaces, truth age, authority ceiling, and stop condition.
6. No member inherits another member's approval.
7. GitHub source, Supabase data/auth state, Cloudflare runtime, and user-visible behavior must be verified as separate layers.
8. Playwright/browser evidence remains required for user-facing completion claims.

Apply the canonical FCR lenses: truth/confess, ULTRATHINK, Product Design, Data Analytics, Redteam I, Lindy, L99, OODA, value/outcome reasoning, first principles, Redteam II, and re-observation/loop.

Each member distinguishes `VERIFIED`, `INFERRED`, `UNKNOWN`, and `BLOCKED`.

Return one packet: `REALITY / COUNCIL / FIX / PROOF / RISK / ROLLBACK / NEXT GATE`.

A green build, migration, deploy, provider response, or Council vote is never enough by itself to certify the real Se’kret Bip user path.
